Source: https://github.com/pulumi/pulumi/issues/20529
Project: pulumi/pulumi

Symptom
=======
After changing @pulumi/kubernetes versions and performing an update that removes/replaces resources, Pulumi sometimes aborts with:

panic: fatal: An assertion has failed: 'Check' and 'Diff' must be called before 'Update' (urn:pulumi:<redacted>::pulumi:providers:kubernetes::eks-provider)

The failure is timing-dependent. Repeatedly switching between two program versions and running `pulumi up --skip-preview` eventually reproduces it. After the panic, the program exits and the Pulumi Cloud operation remains pending until manually cancelled.

Relevant environment
====================
CLI versions observed around 3.162.0-3.191.0.
Kubernetes provider versions include 4.21.1 and 4.23.0.
Linux x86_64.

Reproduction characteristics
============================
The update changes the Kubernetes provider version while resources are also being removed/replaced. It is not consistent across runs and appears timing dependent, which suggests concurrent engine activity rather than a deterministic input-validation failure.
